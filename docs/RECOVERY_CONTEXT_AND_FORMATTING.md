# 1.13.0：显示、网页恢复与上下文延续

配套 Desktop Agent 0.9.0 的上下文延续机制。1.13.0 在 1.12.0 原请求恢复之上，增加 Qwen3.8-Max 繁忙错误卡的严格绑定重试。请同时更新父应用和 `desktop-agent/`，然后重启父应用。默认双栏并排、Qwen 保留当前模型选择以及录制 Skill 的显式确认流程继续有效。

## 本次日志说明了什么

日志中的 `HTTP 200` 只说明某个生成请求收到了 HTTP 响应头，不能据此认定输入已被网页接受或回答已经完整。该轮随后出现 `submission_unconfirmed`，父接口以 `candidate_generation_failed` 结束，Agent 因此停在已执行 5 个工具步骤的位置。

旧交互入口在下一次输入时新建了独立运行，未带上此前目标与工具记录，所以“继续”被模型理解成没有历史的独立问题。本版在同一交互进程中保留执行上下文，并将网页恢复放在原请求内处理。

## 1. 修复异常引用与中文换行

给定例子中，句号、字面量换行及下一项编号被挤进了链接标签，并同步污染了网址路径。Agent 对最终自然语言结果增加有条件的修复：

- 恢复中文句子内的异常软换行，将下一项编号移回列表正文。
- 域名与污染形态完全对应时，去掉失效超链接，显示 `来源：www.bbc.com（链接异常）`；不会编造原始报道网址。
- 保留合法链接、代码、路径以及动作 JSON 的原始语义。修复前正文仍在模型日志与运行记录中，格式化后的内容用于终端和结果 Markdown。

原文中的第三条会作为独立的 `3. 陪伴经济新尝试…` 显示，不再嵌在 BBC 链接中。这个处理修正排版，不验证新闻事实；无法确定的其他损坏链接保持原文，供诊断使用。

## 2. 网页失败后恢复当前回答

恢复保留原请求、原网页会话、原提示与采集基准，不刷新网页，不新建聊天，也不重新填入长提示词。

| 阶段 | 行为 |
|---|---|
| `retrying` | 检测到本轮明确错误、匹配本轮用户输入及可用重试按钮后，最多自动点击一次 |
| `manual_retry_required` | 自动重试没有效果、按钮无法确认或发送接收状态不明时，提示用户处理当前模型网页 |
| `recovering` | 观察到本轮确实恢复后，继续等待完整回答，再交回 Agent 解析和执行 |
| `recovery_timeout` | 恢复窗口结束仍未取得完整回答，明确失败并保留诊断和 Agent 上下文 |

收到人工提示时，在对应模型网页点击当前回合的“重试/重新生成”。如果完整提示仍在输入框，请先检查，再手动发送。保持当前会话，不要再次粘贴整段提示。后台标签页可通过父界面的“处理网页重试”入口显示正在等待人工处理的模型。

### Qwen3.8-Max 截图中的繁忙卡

针对“Oops! There was an issue connecting to Qwen3.8-Max / 目前服务访问量较大，请稍后再试”红色错误卡，程序可以识别卡片下方没有可见文字的圆形箭头，并兼容“当前服务访问量较大”文案；图标按钮带精确重试 `aria-label` / `title` 时也可识别。但图标形状本身不会授权点击；只有同时确认下列条件才会自动点击一次：

- 本轮用户消息已出现，且与原提示完全关联；错误位于该用户回合之后。
- 错误文案匹配该 Qwen 繁忙卡，图标位于同一回合的局部容器内，且页面中只有一个候选。
- 控件可见、可用、在视口内、未被遮挡并通过命中检测；页面没有正在生成。
- provider origin、当前会话 URL 和用户消息历史均未变化。

候选多于一个、本轮绑定不明确或按钮无法点击时，程序不猜测，进入 `manual_retry_required`。更完整的检测条件和日志见 [Qwen 发送与重试](QWEN_SEND.md)。

恢复窗口内无需在 Agent 输入“继续”：原 HTTP 请求还在等待，成功采集后会自动执行后续步骤。窗口已经超时后，旧请求停止采集，此时才使用下节的“继续”保留上下文重新请求模型。

在父应用高级设置或配置中调整：

```json
{
  "generation": {
    "recovery_timeout_seconds": 180
  }
}
```

默认 180 秒，范围 0–600，0 表示关闭自动点击和人工恢复等待。这不会放宽成功判定：明确的网页错误卡仍标记该候选失败，不会当成 Markdown 回答或进入融合。默认 `allow_partial: false` 时会阻止整轮融合；显式开启部分结果时，只使用其他成功来源。

窗口从首次进入异常恢复开始计时，同时不超过原生成截止时间加恢复预算；再次人工点击不会重置计时。配套 Agent 从已验证身份的父服务状态读取总等待预算，避免人工操作期间客户端提前超时。其他 OpenAI 兼容服务沿用其配置的请求超时。

已明确失败的网络流，必须观察到新的关联生成请求才可解除失败。失败后显示的缓存尾片、移除错误提示或静态的旧答案不能冒充恢复成功。无法确认本轮用户消息、切换会话、出现其他用户输入时，也不能混收其他回答。所有候选完整成功后才进入融合；取消及超时仍会结束本轮。

恢复期间仍强制 origin 绑定。如果页面为了 OAuth 或验证跳到其他站点，本轮会以 `provider_origin_changed` 明确停止，不会在跨站页面继续输入、点击或采集。请在应用空闲时完成登录，回到配置的模型 origin 后再发起请求；详见 [浏览器登录导入](BROWSER_LOGIN.md)。

## 3. “继续”和补充提示继承当前上下文

```text
agent[qwen]> 整理工作区文件，并生成报告
…网页恢复超时，任务未完成…
agent[qwen]> /context
agent[qwen]> 继续
agent[qwen]> 报告中再增加失败原因和来源
agent[qwen]> /new
agent[qwen]> 开始一个无关的新任务
```

- “继续”带上原目标、模型回复、工具结果、失败动作和待核验状态。新的自然语言提示也追加到当前上下文；切换模型不清空上下文。
- 每轮仍有单独的任务记录。显示的工具步骤只计本轮新执行步骤；既有历史保持原状态，不被改写成成功。
- `/context` 显示当前摘要，`/new` 清空内存上下文并建立新的交互会话分组，保留历史文件。`/retry` 在当前上下文中再次提交上一提示。
- 启动检查失败、模型尚未收到的新输入仍会保留；随后“继续”会带上这条输入，避免只恢复更早的目标。
- 已派发过的相同修改动作不会自动重放。读取可重新执行；未知执行结果和待核验操作仍需核验，不能直接输出“任务完成”。新一轮浏览器、桌面元素引用需重新获取；浏览器核验必须对应原目标页面。
- 临时能力授权不会从历史记录继承，工具仍按本轮权限和工作区检查。上下文超限会明确停止，不静默丢弃已有任务内容。

上下文延续仅适用于当前交互进程。重启后的 `/history`、`/sessions` 可查询旧任务，但不会从日志恢复执行，也不会执行历史中的命令。单次 `run "任务"` 调用仍各自独立。Skill 录制期间，“继续”、`/new` 和 `/context` 是录制步骤文字；录制结束与确认仍由专用命令控制。

## 排查与验证

详细记录持续写入日志文件；Agent 默认终端只显示必要步骤、网页阶段、选择提示和格式化结果。使用 `/verbose on` 查看路径，`/pack` 打包脱敏诊断；需要分析正文时显式使用 `/pack --include-content`。

重点查看 `adapter.recovery_started`、`adapter.recovery_target`、`adapter.recovery_retry`、`adapter.recovery_manual_required`、`adapter.recovery_observed` 和 `run.continued`。最终 `recovery_timeout` 的 `details.original_code` 保留原始异常原因。

本地验证使用真实 localhost HTTP、临时文件操作和模拟 DOM/CDP。没有登录真实 ChatGPT、Qwen、DeepSeek、GLM 或 Kimi 账号，未在用户 Linux 桌面完成原生 Electron 实站验证。站点错误面板、用户消息和按钮结构可能随账号或版本变化；无法确认当前回合时保留失败，需要结合“检测发送按钮”和实际网页诊断。完整测试结果见 [验证记录](TESTING.md)。

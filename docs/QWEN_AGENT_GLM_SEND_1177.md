# 1.17.7：desktop-agent 的 Qwen 长输入与 GLM 对话发送

基线：完整的 `multillm-fusion-1.17.6-qwen-network-retry.tar.gz`。父应用版本为 1.17.7；desktop-agent 代码和版本 0.16.1 未改动。本包不包含用户配置、运行日志或登录信息。

## 诊断范围

用户报告：Agent 请求 Qwen 时出现网络错误，父应用普通对话未出现；父应用多模型模式没有把问题发送到 GLM。本轮没有新的现场网络日志、DOM 快照或账号会话，因此不能确定线上 Qwen 是请求长度、服务端限流、网络故障还是其他原因。

源码和后端接口测试确认：Agent 单模型 API 与父应用对话都经由相同的 Bridge、Electron WebsiteAdapter、已登录网页发送，不存在本次新增的另一套远程 Qwen API。主要输入差异是 Agent 携带系统要求、工具参数说明及完整历史；不能只比较用户输入的几个字。旧版本先等输入框可用，再取得目标页面的显示与焦点；对显示后才挂载编辑器的页面，这个次序可能一直等待不到 GLM 输入框。点击的 CDP 确认也不等于站点已完成异步提交。

本次修复了本地可复现的输入框发现、长文本输入和提交时序问题，同时增加诊断。分段输入不减少最终请求大小，不绕过站点上下文限制、限流、登录或验证码。

## 发送流程

1. 复用 Qwen / GLM 当前页面，仍通过原有会话检查保留手动选择的模型。
2. 取得短时网页交互权限、显示并聚焦目标页面，然后等待输入框；不再先在隐藏页面里空等。
3. 识别实际编辑器、检查已有草稿和真实 HTML maxlength。超过明确限制时停止，报告长度，不截断或覆盖。
4. 长 textarea 默认按 4096 个 UTF-16 代码单元分段，用 CDP 原生输入逐段追加；避免分开 emoji 的代理对。每段前后核对已有文本与期望前缀、焦点、光标位置，默认间隔 35 毫秒。普通短输入仍是一次原生编辑。
5. contenteditable / ProseMirror / tiptap 富文本编辑器保留一次完整原生输入。实际 Chromium 测试发现分段编辑可能受段落光标和空格归一化影响，因此不对富文本强行分块；最后仍作完整文本核验。
6. 核验完整内容后，仅点击一次发送。Qwen / GLM 默认最多保持交互页面 2 秒，观察到本轮生成请求、生成状态或新回答就提前释放；用户消息本地回显本身不等于网络提交。
7. 释放后继续等待接收确认和完整回复。第二模型不必等第一模型完整回答才开始输入。

发现前缀变化、输入框替换、焦点/光标变化时，停止继续追加，保留现场；没有自动清空草稿、重输全文或补点发送。发送后页面保持时间是有限上限，不是对异步提交的绝对保证；超过上限仍继续原有确认流程，不盲目重发。

## GLM 输入框识别

增加对 `#chat-input` 富文本编辑器、包装层内部编辑器、无 `role=textbox` 的 ProseMirror/tiptap 和可确认的发送按钮的识别。自定义旧选择器仍优先；失败时使用程序内补充选择器。

最后的语义后备只允许唯一的可见编辑器，且需要明确发送控件。过滤搜索/反馈输入、对话框及消息内容中的示例输入框/按钮；多个候选或被遮挡、禁用时停止，不猜测控件、不退回盲目 Enter。GLM 必须在设置中已启用并登录，本版不自动启用未选择的模型。

多段富文本按段落及换行读取，处理空段落占位 `<br>`，避免把视觉间距误当作额外输入。既有的首次会话地址绑定、切换会话保护、模型选择校验继续保留。

## 配置与超时

设置 → 等待与完成判断 → 长输入与发送稳定性：

| generation 字段 | 默认值 | 允许范围 |
|---|---:|---:|
| input_chunk_chars | 4096 | 整数 256–16384 |
| input_chunk_delay_ms | 35 | 整数 0–1000 毫秒 |
| submit_settle_seconds | 2 | 0–10 秒 |

点击保存后写入父应用配置，后端严格校验并传递到网页任务；旧配置缺字段时自动使用默认值。0 秒保持相当于发送点击后立即释放交互页面，不建议用它排查异步提交问题。

多模型候选仍共享原有默认 60 秒总时限。页面准备、分段输入、发送后保持、限速、重试和人工验证都计入此时限，不会额外加时。单模型输入框准备最多等待 45 秒；存在共享候选时限时，此准备环节上限还受剩余预算约三分之一及 15 秒约束，防止未登录页面独占整轮。整合仍需所有候选完成且原文已保存；只有明确启用部分结果才允许按原规则处理失败。

上一版 Qwen 当前回合明确错误的单次重试继续保留，不会因新增长输入逻辑重复发问题。验证码仍是检测后人工处理，不绕过、不自动拖动。

## 新增诊断

- `adapter.start`：本次实际完整提示的字符数、UTF-8 字节数、SHA-256。
- `adapter.input_chunk`：第几段、共几段、累计长度。
- `adapter.input_acknowledged`：`cdp_verified_chunks` 或 `cdp_insert_text`、段数及提示摘要。
- `adapter.submit_settle_started/finished`：页面短时保持及释放证据。
- `adapter.request_payload`：CDP 通知已有 postData 时记录请求体字节数及匹配状态，不额外抓取正文。
- 原有 `adapter.network_response` / `adapter.network_failed`：HTTP 状态或实际网络错误；失败提示现在带上已检测到的 HTTP 状态/错误码。

`prompt_match=exact` 仅表示已提供的 JSON 请求体中存在与完整提示相等的字符串，不证明服务端已接受或生成成功。`unavailable` 表示 CDP 未提供正文；`unverified` 表示不是可识别的 JSON 或未找到精确字符串，不能据此认定数据被截断。未知生成端点仍保留原有 DOM 观察，不伪造网络确认。

新增摘要记录不包含正文、请求头或 Cookie。原有完整请求/回复诊断仍可能包含任务和文件内容；分享日志前应检查私人信息。再次失败时优先提供父应用的请求编号、`adapter.failed`、上述输入摘要和网络状态，Agent 的 502 包装信息不足以定位站点原因。

## 更新

必须关闭旧父应用和旧 Agent，再从新路径启动父应用。仅运行新目录中的 Agent 仍可能连到正在运行的旧父服务，无法使用这次网页适配器修复。

```bash
mkdir -p fusion-1177
tar -xzf multillm-fusion-1.17.7-qwen-agent-glm-send.tar.gz -C fusion-1177
cd fusion-1177/multillm-fusion
node -p 'require("./package.json").version'  # 1.17.7
./run.sh
```

父应用就绪后再使用 Agent：

```bash
./desktop-agent/run.sh chat --model qwen
```

已有父应用配置和浏览器登录数据无须删除；不要用示例配置覆盖个人配置。更换目录时可复制自己的 `desktop-agent/agent.config.json`，核对其中父项目目录、日志目录等绝对路径。Agent `--version` 仍显示 0.16.1 是正常的；父应用 `/internal/status`（需要原有鉴权）新增 `version: 1.17.7`，用于核对实际服务。

增量补丁仅适用于原始 1.17.6；有个人源码改动时先备份，再执行 `patch --dry-run -p1`。完整包优先，避免旧文件残留。

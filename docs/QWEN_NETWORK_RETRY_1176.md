# 1.17.6：Qwen 网络错误自动点击当前回合重试

基线：完整 `multillm-fusion-1.17.5-json-glm-fix.tar.gz`。父应用为 1.17.6，Agent 保持 0.16.1；Agent、本地 JSON 纠正和配置代码未改动。

## 触发与行为

本版覆盖用户报告的页面提示：

```text
Oops! There was an issue connecting to Qwen3.8-Max.网络错误
```

也兼容完整 Qwen 连接错误标题配合“网络异常”“网络连接错误”“Network error”“Failed to fetch”等原因，以及此前“目前/当前服务访问量较大，请稍后再试”的提示。模型标签从页面文案识别，不硬编码为某一个 Qwen 型号；这不是对任何线上模型版本可用性的声明。

确认本轮用户消息已出现、内容与本次提示相符后，检测该助手回合中的错误卡和其局部重试控件。支持精确的重试文字、aria-label/title 及紧邻错误卡的单一图标按钮，包括单回合包装内的相邻页脚；不在整个页面搜索任意“刷新”图标。

每个任务最多进行一次自动重试点击。主进程通过原有 CDP 输入通道完成点击，DOM 检测本身不调用 `click()`。不刷新、不重新填入问题、不新建另一会话，也不改变已选择的模型。确认新一轮生成请求或生成指示出现、当前错误消失且回复完整稳定后，才返回原文；点击回执、HTTP 200 和错误卡消失都不能独自算作成功。

原实现只在恢复入口检查一次按钮。本版在恢复预算内继续检查 Qwen 的当前错误和按钮，因此网络请求先失败、错误卡或按钮稍后才渲染时仍有机会自动重试。旧错误卡不作为正常回答保存或交给融合。

## 避免重复请求

以下情况不会额外点击：本任务已经自动点击过；点击/预留回执不确定；人工或站点已开始另一轮生成；当前页面仍在处理响应；会话、用户消息或草稿已变化；选中模型被更改；验证码需要人工处理；按钮不唯一、不可见、禁用、被遮挡或无法命中。

在等待输入占用、预留按钮及真正发出 CDP 点击前再次检查网络，避免另一模型占用输入期间，用户已手动重试而程序随后又补点。一次失败的人工请求也不会因失败计数重置而重新获得自动点击资格。

无法安全找到按钮或自动点击后仍失败时，继续使用原有人工恢复提示，并在截止时间结束后明确失败。缺少用户消息包装时，只阻止错误卡成为答案，不猜测它属于当前任务。

## 配置与界面

沿用现有设置，无新增配置迁移：

```json
{
  "generation": {"recovery_timeout_seconds": 180},
  "chat": {"timeout_seconds": 60}
}
```

这是配置片段，不应拿它覆盖完整配置。`generation.recovery_timeout_seconds` 默认 180 秒，取值 0–600；0 表示关闭自动与人工恢复等待，此时错误立即报告，仍不会当成答案。设置中对应“等待与完成判断”页面的“网页异常后的恢复等待（秒）”。

多模型候选阶段仍共享 `chat.timeout_seconds` 的总时限，默认 60 秒。重试、限速和恢复等待都包含在这 60 秒内，不会额外再增加 180 秒。整合阶段和单模型 Agent 请求沿用各自现有超时设置。

点击时模型状态显示：

```text
Qwen 网络错误，正在点击当前回合的“重试”（1/1）…
```

观察到恢复后继续等待完整回答。另一模型可独立继续生成；默认仍需全部候选成功、原文保存完成后才融合。

## 日志

- `adapter.recovery_waiting_target`：Qwen 等待迟到错误卡/按钮的原因与剩余秒数。
- `adapter.recovery_target`：按钮是否就绪及 `error_kind`。
- `adapter.recovery_retry`：`attempt: 1`、`max_attempts: 1`、`error_kind: qwen_network` 或 `qwen_busy`。
- `adapter.recovery_auto_skipped`：人工/站点生成已开始，或预留期间出现新请求而跳过自动点击。
- `adapter.recovery_observed`、`adapter.complete`：分别表示有恢复证据、已获取完整回答。

这些新增事件不包含错误正文、输入内容或凭据；原有请求/回复日志策略没有改变。

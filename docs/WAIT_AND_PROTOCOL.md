# 1.6.0：慢响应、完整融合与 Agent JSON

本文保留 1.6.0 的行为记录。1.8.0 起 Agent 的详细日志只同步到全局和本轮文件，终端改为步骤、选择提示和格式化结果；当前说明见 [Agent 终端与 JSON 修复](AGENT_TERMINAL_AND_JSON.md)。

请同时更新父应用和 `desktop-agent/`，关闭旧进程后重新启动。已有模型配置、登录会话和数据继续使用原目录；新版启动时自动迁移旧配置。

## 默认并排及慢响应

两个以上模型启用时，首次启动或首次升级默认双栏并排；保留旧版选择的模型和宽度比例。随后主动选择标签页或独立窗口会继续保存。只有一个模型启用时使用标签页。

输入操作仍逐个进行：目标网页获得可见视口和焦点，输入完成并回读一致后，仅投递一次发送手势。完整点击或按键的 CDP 回执到达后释放输入占用，其他模型即可发送；Qwen 的接收确认和生成等待继续进行。释放输入占用不代表网页已经接收，也不触发补发。

设置中的等待时间：

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `generation.submission_timeout_seconds` | 120 秒 | 投递后等待网页接收证据，允许 15–600 秒 |
| `generation.timeout_seconds` | 600 秒 | 单次来源任务的总等待，包含页面准备、输入排队、确认和生成 |
| `fusion.timeout_seconds` | 600 秒 | 来源全部完成之后，另一次整合任务的等待 |
| Agent `timeout` | 900 秒 | 单次 API 调用等待；已有自定义配置保持原值 |

接收等待同时受剩余总时限约束。延长接收等待但保留较短总时限，不会延长总时限。使用 `web-fusion` 的 Agent 可能需要更长 HTTP 超时，因为候选生成与融合先后执行；Agent 通常直接指定一个模型。

检测到发送后、匹配生成接口路径的 POST 响应仍在进行时，页面文字暂时稳定也不会被视为完成。无关 SSE 通知连接不纳入完成门禁。没有识别到生成请求时仍结合新回答、停止按钮和稳定窗口判断；网页没有统一完成接口，这种 DOM 回退存在站点差异。网络状态本身不等于已获得可用回答。

后端等待所有候选任务到达终态，默认要求全部成功才开始融合。只要有一个来源超时或失败，就返回具体错误并保留已成功来源，不用剩余模型冒充完整融合。设置页仍提供明确的“允许部分结果”高级选项，但默认关闭。

旧 `schema_version:1` 配置只迁移一次到 2：关闭 `allow_partial`，将旧默认 180 秒改为 600 秒，补充 120 秒接收等待；其他自定义超时和站点配置保留。新版明确修改的部分结果设置不会在下次启动被重置。

## 本次 JSON 错误的原因与修复

用户日志中的数组 `\[...\]` 和 `[https://www.youtube.com](https://www.youtube.com/)` 可以由旧版 HTML → Markdown 转换复现：网页显示的合法 JSON 被转换器再次加入 Markdown 转义，导致 Agent 在执行前拒绝解析。

新版先识别整个回答是否为合法 JSON 对象或单独的 JSON 代码块，适合保留的页面结构直接返回 JSON 原文，日志记录 `extraction_method`。普通文字、列表、表格和代码仍按 Markdown 提取。不会从带解释的文章中抽取一段动作，也不会重新序列化 JSON 来悄悄删除重复字段。

Agent 0.3.0 同时兼容这类旧回复：严格解析失败后，只去掉 JSON 字符串外数组括号的 Markdown 反斜杠；只在 `browser.open.arguments.url` 中解包显示地址与目标一致的完整网址链接。字符串中的命令、转义和内容保持原样。地址不一致、重复字段、多对象和其他无效协议仍拒绝执行，必要时请求格式修正。具体修复通过 `model.protocol_normalized` 记录原文、变更和动作。

## 每轮日志和结果

启动 Agent 时终端会显示准确路径：

```text
desktop-agent/.runtime/logs/agent.log
desktop-agent/.runtime/runs/<run_id>/events.jsonl
desktop-agent/.runtime/runs/<run_id>/result.md
```

同一条结构化日志同步写入终端、全局日志和本轮 `events.jsonl`，每条立即 flush。全局日志继续轮转，本轮日志不轮转。失败或停止也写 `result.md`，包含状态、步数及错误；成功时兼容生成 `final.md`。记录包括模型原始回复、协议纠正、工具参数/结果和核验过程，凭据继续脱敏。

每轮文件权限为 0600，拒绝覆盖已有任务日志或跟随符号链接。某个日志文件不可写时会明确告警，其余输出继续；应按终端提示检查实际路径和磁盘。

复现后在父目录打包，例如：

```bash
./package.sh --include-content --agent-run-id 20260909T032443Z-69d70e4c
```

`--agent-run-id` 额外选择该轮 `events.jsonl`，可重复；不会收集 `transcript.json`、`state.json`、工作区、截图或浏览器配置。旧版任务尚未生成该文件时，清单会提示不存在，仍收集全局日志。自定义 Agent 运行目录另加 `--agent-runtime-dir /path/to/agent-runtime`。

本次自动验证采用本地 HTTP、DOM 和 CDP 夹具，没有登录真实 Qwen/DeepSeek 账号。现场应核对两份来源完整保存后才出现融合事件；出现失败时默认不应发起融合。

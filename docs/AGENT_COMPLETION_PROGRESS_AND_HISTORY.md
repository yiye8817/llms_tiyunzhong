# 1.10.0：Agent 输入补全、网页进度、动态技能与历史

配套 desktop-agent 0.7.0。请同时更新父项目和子目录并重启父应用：网页进度需要 Electron、父 API 和 Agent 三端配合。已有配置、登录和日志请保留；本版不要求重新登录或每轮刷新 Qwen。

## 输入与显示

```bash
cd multillm-fusion/desktop-agent
./run.sh                    # 默认进入交互，必要步骤和格式化结果
./run.sh --v                # 额外显示工作目录、任务编号与结果文件位置
./run.sh run '解释当前项目' --v
```

`-v`、`--v`、`--verbose` 等价，可放在子命令前或后。在普通 Linux 终端输入时，灰色文字表示尚未接受的候选：

- Tab 或行末右方向键接受候选，回车才提交任务；行中右方向键仍移动光标。
- ↑/↓浏览历史输入，支持 Home、End、删除、中文与多行粘贴。粘贴不会拆成多次自动执行。
- 建议来自本地交互命令、模型 ID 缓存、当前 Skill 目录及历史任务，不按键调用模型。
- `/models`、`/model 模型ID` 会读取接口模型列表并更新缓存；后者校验后切换后续任务。
- 非 TTY 或 `TERM=dumb` 使用普通行输入；`NO_COLOR` 禁用灰色候选及候选接受，保留编辑与历史功能。

默认隐藏自动输出的目录与文件位置，不影响全局日志、本轮日志、原始对话及 Markdown 结果落盘。`/verbose on` 开启详细显示，`/verbose off` 关闭；`/logs`、`/status`、`/pack` 是主动查询，仍显示相应路径。错误原因、权限选择以及任务答案本身涉及的文件路径不会被隐藏。

## 网页的实际阶段

终端按当前请求及模型展示网页进度。不同网站可观察到的信号不同，阶段可能跳过或交错出现；不会按固定计时器虚构完成状态。

| 显示内容 | 依据和含义 |
| --- | --- |
| 请求已排队／准备网页 | 父服务排队及目标网页准备事件 |
| 已投递发送动作，等待网页接收 | Electron 已完成点击或键盘投递；此时不能证明网站接受 |
| 网页已接收请求 | 输入、消息或生成状态满足网页接收核验 |
| 生成服务器已返回，HTTP 状态 | 观察到当前生成 POST 的实际响应状态；HTTP 200 不代表答案完整 |
| 正在等待或接收网页响应 | 生成网络请求尚未完成，但当前没有足够 DOM 信号证明正在生成 |
| 网页正在生成回答 | 有停止按钮或回答生成等实际页面信号 |
| 等待完整回答并采集 | 采集与稳定性核验中，仍受完整 JSON 和全部来源完成要求约束 |
| 网页回答已采集／响应已返回，正在解析 | 单模型采集完成／本次 API 回复可交给 Agent 解析；不是整个任务执行完成 |

父 API 在已有认证下提供 `GET /v1/progress/{UUID}?after=N`，并接受聊天 POST 的 `X-Fusion-Progress-ID` 关联头。Agent 只在父服务声明 `web_progress` 能力后开启只读轮询；普通兼容 API 不发送该头或额外轮询。若进度接口不可用则退回通用等待，不会因此重复提交聊天 POST。

每个关联 ID 只返回该请求的阶段、模型、序号与观察到的 HTTP 状态；不返回网页 URL、提示词、答案正文或思考内容。终态进度短期保留，完整诊断继续写入原日志文件。

## 动态 Skill

```text
/skill-demo workspace-report-demo
/skill test workspace-report-demo
/skill load workspace-report-demo
检查当前工作目录并给出报告
/skill reload
/skill unload workspace-report-demo
/skill run workspace-report-demo 检查当前工作目录并给出报告
```

生成后立即能在 `/skills` 与输入候选中发现，无需退出 Agent。`load` 将技能加入后续任务，`unload` 移除；`run` 只为本次任务附加指定技能，`/retry` 保留这次指定并使用当前模型与工作区。每个任务重新读取已选技能正文，编辑文件后不会继续使用旧缓存；`reload` 可提前检查当前已选文件。

生成命令会输出明确的加载、静态检查和实际运行方法。独立终端用法：

```bash
./run.sh skill-demo workspace-report-demo
./run.sh skill-test workspace-report-demo
./run.sh run --skill workspace-report-demo '检查当前工作目录并给出报告'
```

`skill-test` 检查名称、frontmatter、非空正文、支持的资源引用及 Python 脚本语法，不执行脚本。静态检查通过不代表任务或外部依赖已经运行成功；实际验证需运行上述任务并检查结果。非 Python 脚本不会被假定已通过语法测试。完整编写规则、目录结构和示例见 [Agent README](../desktop-agent/README.md) 与 [Skill 编写说明](../desktop-agent/docs/SKILL_AUTHORING.md)。

## 历史与会话查询

```text
/history
/history 系统报告
/history show 任务编号
/sessions
/session 会话编号
```

```bash
./run.sh history '系统报告' --limit 10
./run.sh history --show 任务编号
./run.sh sessions
./run.sh sessions 会话编号
```

历史详情显示保存的用户输入、状态、模型、工具执行摘要和格式化答案；不把系统提示、工具原始参数和输出展开成终端日志。查询命令只读本地记录，不启动父服务、不调用模型，也不会把旧任务注入当前任务。历史答案同样不意味着现在已执行该任务。

新版本按一次交互终端建立会话索引；旧版本已有的独立任务仍可通过 `/history` 查询，没有索引的旧任务不会虚构归属。`/retry` 只重跑当前交互中的上一任务，不自动恢复历史中的浏览器句柄或授权。记录不存在或损坏时会给出错误或跳过不可读条目，不执行内容。

## 缺失工具与 CLI 替代

| 情况 | 处理 |
| --- | --- |
| `file.read`、`file.list`、`file.write` | 精确映射到已注册的 `files.read`、`files.list`、`files.write`，保留并校验原参数 |
| 参数名或参数类型不合法 | 在派发前要求模型修正，修正通过后才执行 |
| 未注册工具 | 查找实际工具目录及本机已安装 CLI，提供候选并要求模型重新规划 |
| 启动前确认可执行命令不存在 | 可提出等价操作；新动作仍需经过 schema、权限和目标范围检查 |
| 超时、结果不确定、已经启动后失败 | 不当作“从未执行”自动重放；保留失败及核验要求 |

候选 CLI 只表示命令存在，不保证语义或参数兼容。使用 CLI 必须通过 `shell.run` 的 `argv` 参数和原有 shell 能力授权；自动别名也不绕过文件工作区限制。完整读取同一目标可用于核验明确的未启动读取失败，读取别的文件或截断结果不会清除原失败。终端显示简要替代步骤，原工具、候选与实际结果写入日志。

## 验证边界

自动测试覆盖真实本地 HTTP、模拟网页桥接、POSIX 终端键盘/粘贴、并发日志、历史文件和本地工具。当前交付环境未登录真实模型网页，未完成用户 Linux 图形桌面的 Electron、Qwen 或其他模型网站端到端验证；网站改版或不同账号布局仍需结合发送诊断与实际日志检查。

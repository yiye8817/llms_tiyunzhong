# Qwen 界面对话三级重试修复 — 1.17.10

父应用版本为 1.17.10；desktop-agent 保持 0.17.0。本次修改必须重启父应用才会生效，只重启 Agent 不会更新网页适配器。

## 为什么上一版可能没有进入三级重试

在未修改的 1.17.9 上，用真实 Chromium 和生产适配器复现了四种故障。测试页面、网络通知和人工点击是模拟的，没有使用真实账号。它们说明代码中存在可触发用户所见现象的路径，但不能在缺少本次现场日志时断定线上只有这些原因。

1. **请求已经失败，页面仍显示停止生成。** 旧代码把残留的 busy/停止按钮当成真实在途生成，导致第一级跳过，随后等待一直拖到总超时，第二、三级不出现。
2. **错误卡缺少常见角色或 alert 属性。** 网络失败文案确实在当前用户消息后面，但旧选择器没有找到对应错误卡。
3. **HTTP 200 内含错误对象。** 旧代码只看到 HTTP 成功和页面占位文字，可能没有进入错误恢复。新版仅对已经归属本轮生成的、小型 JSON/SSE 响应做本地错误封装检查。
4. **重试只有图标。** 第一级脚本点击未产生请求后，旧代码丢失已确认的图标控件线索，第二级截图无法匹配该控件。本版保留只读定位线索，但不会重新授权第二次脚本点击。

## 修改后的实际行为

统一对话和 Agent 继续共用同一适配器，不是新增另一套网络请求。候选请求日志增加 `source: fusion_chat`，普通单模型 API 为 `api`。

```text
检测当前回合的网络/页面错误
  → 第 1/3 级：调用已确认重试控件的页面点击处理逻辑
  → 未发现新生成：第 2/3 级，截图、复核当前控件、CDP 原生点击
  → 仍无新生成或不能安全点击：第 3/3 级，人工提示与倒计时
  → 检测到新生成：停止补点，等待完整回答
```

第一级默认等待 3 秒确认新请求；人工等待默认 20 秒。某一级成功后不会为了凑齐三级再次点击。每轮自动页面点击和自动原生点击各最多一次，不刷新页面、不重新填入原问题、不重放 HTTP 请求体。无法定位时记录跳过原因，不盲点任意图标。

只有本地网络追踪证明**最新生成已经终止失败、没有在途请求，同时当前用户消息及错误卡通过核验**时，才忽略残留的停止标志。旧请求失败不能用来忽略新请求的 busy 状态。真实会话切换、其他用户输入、跨域跳转和验证码等仍保留原有保护。

HTTP 200 错误检查限制为已归属本轮的 JSON/SSE 响应，最多 262144 字符/限定响应长度。读取等待最多 1.5 秒且受本轮截止时间约束；只返回错误类别和可识别的状态码，不把错误正文写进新增日志。普通回答里的“502”或 JSON 示例不会触发重试。检查失败或响应过大时仍依靠原有页面/网络检测，不猜测其内容。

人工点击只记录当前回合中的可信控件；只有该点击之后发生新生成并获得完整答案，才提升为下次可复用记录。不能绑定当前错误控件时，人工可以继续操作，但不会学习一个未经核验的目标。

## 界面状态和超时

候选面板显示以下本地运行状态，而非直接显示网页中的任意文字：

```text
Qwen · 第 1/3 级：页面重试
Qwen · 第 2/3 级：截图定位并点击
Qwen · 第 3/3 级：等待人工重试 · 剩余 20 秒
```

仍使用设置中的 Qwen 分级重试、截图辅助、重试学习、触发确认等待、人工等待等字段。默认分级重试开启、人工等待 20 秒，网页异常后的恢复等待默认 180 秒。用户已关闭的选项不会被升级强制覆盖。

**双模型候选默认共享 60 秒总时限。** 输入、生成、重试和人工等待全部计入其中。错误在第 55 秒出现时，不能承诺再额外提供完整 20 秒。剩余预算不足时显示实际剩余时间；总时限已耗尽、用户取消、恢复等待为 0 等原因会进入进度/日志，不再无声跳过。需要更长窗口时，在设置中显式增加多模型候选回答总等待时间。单模型 API 继续使用其已有生成和恢复预算。

本功能处理统一对话/API 已提交并正在跟踪的任务；不是对用户在网页中任意手工发起、与本地任务无关的聊天进行常驻自动点击。

## 日志与隐私

```text
logs/retry/qwen/<本轮时间与标识>/attempts.jsonl
logs/retry/qwen/<本轮时间与标识>/*.png
~/.local/share/multillm-fusion/retry-learning/qwen.json
```

沿用 FUSION_LOG_DIR / FUSION_RETRY_DIR / FUSION_RETRY_LEARNING_DIR 等已有覆盖设置。初始化/落盘失败会写诊断，但不会把文件保存失败伪装成重试成功。

重点事件：`adapter.retry_eligibility`、`adapter.retry_stage_started`、`adapter.retry_stage_result`、`adapter.retry_manual_wait`、`adapter.retry_manual_click`、`adapter.retry_learning_saved`、`adapter.retry_unavailable`、`adapter.network_application_error`。首个事件包括来源、原始错误码、分级开关、恢复预算、剩余总预算和是否可恢复。截屏与控件学习仍沿用原有私有权限和失败处理。

截图可能包含会话内容。`FUSION_LOG_CONTENT=0 ./run.sh` 不保存截图，仍记录必要过程元数据；该选项不等同于删除历史日志或关闭所有学习记录。关闭“重试学习”选项可停止保存/复用学习信息。不要公开原始截图或账号日志。

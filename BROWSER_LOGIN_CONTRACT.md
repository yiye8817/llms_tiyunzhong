# Browser login import contract (v1.2.0)

User requested own Firefox/Chrome/common-browser login reuse. Implement explicit one-way, local, per-model import. No passwords/history import, no background global cookie export, no login data on HTTP routes/logs/UI. No crypto downgrade, DB unlock hacks, browser kill, or OS keyring bypass. User can allow ordinary OS keyring prompt. Imported count never claims site authenticated.

## Scope
Shared `browser-login-sites.json`: provider IDs to fixed root domains and recognized page origins. Main validates selected provider config URL belongs to scope. Python and extension domain checks: host == root or host ends with `.`+root, case-insensitive normalized; never substring.
Default roots: chatgpt=[chatgpt.com,openai.com], deepseek=[deepseek.com], qwen=[qwen.ai,qwenlm.ai], claude=[claude.ai], grok=[grok.com], glm=[chatglm.cn,z.ai], kimi=[kimi.com]. Recognized GLM page origins include `https://chatglm.cn`, `https://www.chatglm.cn`, `https://z.ai` and `https://chat.z.ai`; recognized Kimi page origins include `https://kimi.com` and `https://www.kimi.com`. Do not include generic Google/GitHub/X accounts merely for OAuth.

## Python helper backend/browser_login.py (no FastAPI dependency)
CLI `python -m backend.browser_login` reads ONE JSON input line/object stdin, writes ONE JSON stdout response. No secrets on stderr. Actions:
- `{action:"list"}` -> `{ok:true,profiles:[{id,browser,family:"chromium"|"firefox",name,path}],warnings:[{code,message}],capabilities:{chromium_decryption:boolean}}`. Metadata only, no cookie/keyring reading during discovery. IDs stable hash of canonical source path; extraction resolves fresh list and matches ID (never arbitrary caller path).
- `{action:"extract",profile_id,provider_id}` -> `{ok:true,provider_id,cookies:[{name,value,domain,path,secure,httpOnly,hostOnly,session,expirationDate?,sameSite:"unspecified"|"no_restriction"|"lax"|"strict"}],warnings:[{code,message}],skipped:number}` or `{ok:false,error:{code,message}}`.
Read selected site's own cookies only via readonly SQLite snapshot honoring WAL, with deadline and cleanup, no immutable=1 stale read. Firefox direct stdlib sqlite extraction; skip nonempty originAttributes/container/partitioned/private contexts with count and warning (don't collapse isolation). Chromium unencrypted extraction and browser-cookie3 supported keyring decoding; optional dependency listed `requirements-browser.txt`, default launcher installs it (root owns launcher). Preserve SameSite, hostOnly, Secure, HttpOnly and Chromium epoch. Skip partitioned/top_frame_site_key cookies unsupported by Electron setter; warn. Never return decrypted unrelated domain values. Missing crypto/keyring clean actionable errors and preserved plaintext successes.
Tests use fake home/profile DB fixtures only, stdlib normal Python where possible. Python owner owns tests/test_browser_login.py. No actual credentials here.

## Electron main + browser-login.cjs
Preload additions:
`listBrowserProfiles()` -> Python list metadata above.
`importBrowserLogin({profile_id,provider_id})` -> report only.
`importLoginFile({provider_id})` -> main opens native JSON file dialog, parses/validates snapshot, applies scoped cookies + optional localStorage; returns report or `{canceled:true}`. File bytes do not reach renderer.
Report `{provider_id,imported,skipped,storage_imported,warnings:[{code,message}],source,authenticated:false}`; last field means login unverified, not logged out. Use sentence '已导入 X 项 Cookie；请在网页确认登录' not success-login claim.
Before extraction acquire local browser-maintenance lock; tell backend bridge `{type:"maintenance",active:true}` and wait for acknowledgement `{type:"maintenance",active:true,ok:true}` (backend rejects if busy), before import. During lock block generate/config/other imports. In finally send active:false ack. Backend rejects new chat/config while maintenance and status busy true. Timeout/disconnect stops scheduling new import mutations. Already-submitted Electron cookie setters/isolated-world execution are not cancellable and may finish; retain local lock until they drain, reconnect must withhold ready until this happens. Report partial writes without rollback claims. Root handles backend new maintenance packets. Main handles WS pending maintenance ack. Could simpler use HTTP POST `/internal/browser-maintenance` restricted authenticated; root will implement route? Choose below definitive route.

DEFINITIVE MAINTENANCE: authenticated HTTP POST `/internal/browser-maintenance` body `{active:true|false}` from main only. Acquire returns `{active:true,lease_id}` or409 if busy/maintenance. Release body `{active:false,lease_id}` validates matching. Python engine maintenance contributes busy and blocks submit/config; automatically release when bridge disconnects. Main holds lease until completed and clears finally; main IPC general request MUST NOT expose maintenance route to renderer. Close WS during import cancels helper and refuses further cookie writes. Root owns backend changes.

Only enabled fixed-scope provider, no generation/reload during import. Stop selected view, load about:blank to stop site writes before cookie mutation (keep its sandbox), use exact destination session.cookies.set, omit domain for hostOnly, preserve cookie security/path/expiry. Do not clear all existing cookies; merge updates selected scoped cookies. Import session cookies unchanged (not invent expiry); session login may need resync after restart. Flush store then load configured provider URL. Cookie errors sanitized, no raw exception may contain value. Process stdio max16MiB and timeout90s, no shell; do not pass API token to helper env. `list` timeout10s, no full traceback. Tests injectable fake child runner/sessions and fixture snapshot only. Main owner owns electron/** and tests/test_browser_import.cjs.

## Extension fallback for live cookies + localStorage
Purpose: support encrypted/locked DB or token in localStorage (e.g. some DeepSeek/Qwen versions). Generate extension directories `browser-extension/chromium` and `browser-extension/firefox` with appropriate manifests; shared scripts can be copied into both. Popup explicit current model export only. Request minimal `cookies`, `activeTab`, `scripting`, `downloads` and fixed site host_permissions; no all_urls, no nativeMessaging/network upload. On button click check current tab HTTPS origin scope; `cookies.getAll({domain:root})` for each scope and strict postfilter; get current page localStorage through scripting.executeScript (static code) only matching origin. Export JSON browser download and brief notice local file contains login session.
Format `{format:"multillm-fusion-login",version:1,provider_id,created_at,source:"extension",cookies:[normalized fields as above],storage:[{origin,localStorage:{string:string}}]}`. Skip partitioned cookies with warnings (in snapshot optional warnings array); Firefox containers rejected/skip. Do not gather saved passwords, other sites, IndexedDB/serviceworker/passkeys. Keep cookies in popup memory only, no extension storage. Main may import localStorage by navigating exact recognized HTTPS origin (only matching provider config origin), ensure final committed origin exact before isolated-world injection, merge keys, reload. NEVER inject onto login redirect/other origin. Max512KiB storage, max2MiB JSON snapshot; setter errors include counts only. Mark sites using unexportable state/manual reauth clear.
Extension owner handles all browser-extension/** including README and smoke unit tests tests/test_login_extension.cjs. No real browser sessions invoked.
